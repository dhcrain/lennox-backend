# Frontend for lennox-backend

## Context

`lennox-backend` is a personal FastAPI service controlling 3 Lennox E30 thermostats over the LAN (REST + WebSocket API, bearer-token auth). There is currently no frontend at all, just `curl` commands in the README. The goal is a dashboard the user actually operates day-to-day, mostly from a phone, so it needs to be mobile-first (large tap targets, no hover dependence, installable as a home-screen app) while still being fully usable on a desktop browser.

Locked decisions from discussion with the user:
- Stack: **React + Vite + Tailwind CSS**
- Hosting: **served by FastAPI itself** (single process, single port, same-origin, no CORS needed)
- **PWA**: installable via manifest + service worker

## Backend ground truth (do not re-derive, use as-is)

- `app/main.py`: builds `FastAPI(lifespan=...)`, includes `router` (REST, all behind `verify_token`) and `ws_router`. No `StaticFiles` mount, no CORS middleware today. Custom exception handler returns `{"error": {"code","message"}}`.
- Auth: REST needs `Authorization: Bearer <api_token>`; WS needs `?token=...` query param. No login endpoint, it's one shared token for the whole dashboard.
- `GET /units` → `{"units":[{id,label,ip,connected,last_seen}]}` (`UnitSummary`). Unit count is config-driven (currently 3), don't hardcode.
- `GET /units/{id}` → `UnitState`: `{id,label,connected,temperature,humidity,mode,fan_mode,fan_running,heat_setpoint,cool_setpoint,single_setpoint,setpoint_limits:{min_heat,max_heat,min_cool,max_cool}}`. `heat_setpoint`/`cool_setpoint` vs `single_setpoint` are mutually exclusive per unit depending on the unit's setpoint mode, UI must handle both shapes.
- `POST /units/{id}/mode` body `{"mode": ...}`, `POST /units/{id}/fan` body `{"fan_mode": ...}`, `POST /units/{id}/setpoints` body `{"heat_setpoint","cool_setpoint"}` or `{"setpoint"}` — all return 202 + updated `UnitState`.
- `lennoxs30api` defines the valid enums, not exposed via any route: `HVAC_MODES = {off, heat, cool, "heat and cool", "emergency heat"}`, `FAN_MODES = {auto, on, circulate}`. Frontend hardcodes these.
- `GET /units/{id}/stream?token=...`: sends full `UnitState` immediately on connect, then again only when it changes (on-change push, not per-poll). Closes with code `4401` on bad token/unknown unit.
- Errors: 404 `unit_not_found`, 503 `unit_disconnected` (offline/no data yet), 400 `invalid_request`, 502 `unit_error`.

Keep Node tooling fully isolated under `frontend/`, away from the `uv`-managed Python project. Build straight into `app/static/` (resolved via `Path(__file__).parent / "static"` in `main.py`, robust regardless of cwd). Add `app/static/`, `frontend/node_modules/`, `frontend/dist/` to `.gitignore`.

## Backend changes (`app/main.py`)

- Add `StaticFiles` mount after the existing `include_router` calls: `app.mount("/", StaticFiles(directory=STATIC_DIR, html=True), name="static")`, guarded by `STATIC_DIR.is_dir()` so `uvicorn --reload` still works pre-build.
- Mounts act as a fallback in Starlette, so `/health`, `/units*`, `/units/{id}/stream` keep matching the API router first; only unmatched paths fall through to static files.
- No React Router, no SPA catch-all needed, this is a single-screen dashboard (unit detail is an inline expand, not a route). `StaticFiles(html=True)` serving `index.html` at `/` is sufficient.
- No CORS middleware, same-origin by design.

## Component breakdown (routerless SPA)

```
App
 └─ AuthProvider        (token in state + localStorage, no real login, useAuth())
     └─ TokenGate        (full-screen token entry form if no token stored)
         └─ UnitsProvider (units list + liveState map + per-unit ws status)
             └─ Dashboard
                 ├─ Header
                 ├─ ToastProvider / ToastHost
                 └─ UnitCard[]  (grid, one per unit)
                        ├─ ConnectionStatusBadge
                        └─ ControlPanel (expanded on tap)
                               ├─ ModeSelector
                               ├─ FanSelector
                               └─ SetpointStepper (x1 single, x2 dual)
```

- `src/lib/api.ts`: fetch wrapper, injects bearer token, parses `{"error":{code,message}}` into a typed `ApiError`.
- `UnitsProvider`: `GET /units` once for the id/label/ip list (effectively static). Per-unit live state comes from each unit's WebSocket, which sends full state immediately on connect, no separate `GET /units/{id}` needed in steady state.
- `SetpointStepper`: disable the control until the 202 response (or next WS update) lands, avoid firing a POST per tap.
- State layer: plain React Context + hooks (`AuthContext`, `UnitsContext`). No Redux/Zustand/React Query, overkill for 3 units and low request volume.

## WebSocket management

One `useUnitStream(unitId)` hook instance per unit, called in a loop from `UnitsProvider` (not one shared manager class):
- URL: `` `${wsProtocol}//${location.host}/units/${unitId}/stream?token=${token}` `` (same-origin in prod).
- `onmessage` updates `liveState[unitId]`.
- `onclose` with code `4401`: don't reconnect, clear stored token, kick back to `TokenGate`. Any other close: reconnect with capped exponential backoff (1s→2s→4s→8s, cap ~15s).
- Cleanup on unmount closes the socket and clears pending reconnect timers (guard against stale timers resurrecting a dead socket, standard strict-mode-safe pattern).

## Tailwind / mobile-first strategy

- Tailwind v4 via `@tailwindcss/vite` plugin (single entry in `vite.config.ts`, no separate config/content globbing).
- Grid: `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3` — one column on phone, up to 3 across on desktop, scales if a unit is added.
- Touch targets: minimum 48px (`h-12 w-12`) on all buttons/steppers, generous gaps to avoid mis-taps, no hover-dependent affordances.
- Expanded `ControlPanel` pushes content down (accordion), not a modal, natural scroll on phone.
- `pb-[env(safe-area-inset-bottom)]` at page root for iOS standalone-mode safe area.

## PWA

- `vite-plugin-pwa`, `registerType: "autoUpdate"`.
- Manifest: `name`/`short_name`, `start_url: "/"`, `scope: "/"`, `display: "standalone"`, icons at 192/512 (+ maskable 512, + apple-touch-icon 180).
- Service worker: precache the app shell only (`generateSW`, `navigateFallback: "/index.html"`). **No runtime caching for `/units*`/`/health`** — this is live control data (temperature/setpoints), caching it would show stale values. WS traffic isn't interceptable by a SW anyway.

## Dev / build workflow

- Dev: `cd frontend && npm run dev` (Vite on :5173) with a proxy in `vite.config.ts` for `/units` and `/health` → `http://localhost:8000`, `ws: true` for the stream path. Run backend separately: `uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`.
- Build: `cd frontend && npm run build` with `build.outDir: "../app/static"`, `emptyOutDir: true`. Then `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000` serves everything from one port.
- Document both commands in `README.md`. No CI/deploy pipeline needed for a personal LAN app.

## Implementation phases

1. Scaffold (`npm create vite@latest frontend -- --template react-ts`) + Tailwind + `AuthProvider`/`TokenGate` + `api.ts` + `UnitsProvider` (one-shot `GET /units`) + bare card grid. Wire the FastAPI static mount, confirm `npm run build` → `uvicorn` serves it end-to-end.
2. Unit detail + controls: `ControlPanel`, `ModeSelector`, `FanSelector`, `SetpointStepper` wired to the three POST routes, hardcoded `HVAC_MODES`/`FAN_MODES`, dual-vs-single setpoint branching, `ToastProvider` mapping 400/404/502/503 to readable messages.
3. WebSocket live updates: `useUnitStream`, reconnect/backoff, wire into `UnitsContext.liveState`, drop reliance on per-unit REST fetches.
4. Responsive/mobile polish: verify phone and desktop breakpoints, touch targets, accordion-vs-grid interaction, safe-area insets.
5. PWA finalization: `vite-plugin-pwa` config, icon set, manifest, install-prompt check on a phone.

## Verification

1. `cp config.example.yaml config.yaml`, fill real IPs + token; `uv run uvicorn app.main:app --host 0.0.0.0 --port 8000`.
2. `curl -H "Authorization: Bearer <token>" http://localhost:8000/units` returns the configured units.
3. `cd frontend && npm run dev`, open `:5173`, confirm token gate, enter token, confirm 3 cards populate via the proxy.
4. Confirm each card's live values match `curl .../units/{id}` output (from the WS initial push).
5. Trigger a control action (e.g. change fan mode) in the UI, confirm the card updates without reload.
6. Force a unit offline (bad IP or powered off), confirm the offline state renders and controls disable (503 path); confirm an invalid mode string surfaces a toast (400 path).
7. Kill and restart the backend with the frontend tab open, confirm WS reconnect/backoff recovers without a manual refresh.
8. Resize to ~375px (single column, large tap targets, no hover reliance) and ~1440px (multi-column grid, not a stretched single card).
9. `npm run build`, restart `uvicorn` without `--reload`, load `http://localhost:8000/` directly and repeat steps 3-6 against the production build.
10. From a phone on the same LAN, visit `http://<host-ip>:8000/`, confirm "Add to Home Screen" appears, install, confirm standalone launch with live data.
